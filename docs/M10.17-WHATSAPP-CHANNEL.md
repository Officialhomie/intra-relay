# M10.17 — WhatsApp channel adapter

## Provider contract checked

Implementation was checked against Meta's current Graph Webhooks guidance and
Meta's official WhatsApp Business Platform Cloud API collection. The relevant
contract is: callback verification uses `hub.mode=subscribe`, the configured
verify token, and the returned `hub.challenge`; event bodies are signed in
`X-Hub-Signature-256` as `sha256=` plus HMAC-SHA256 over the exact raw body;
inbound messages arrive under the `whatsapp_business_account` / `entry` /
`changes[field=messages]` envelope; and outbound text is posted with bearer
authentication to `/{phone-number-id}/messages` for an explicitly configured
Graph API version. Successful event notifications receive HTTP 200. Failed
processing/delivery receives non-2xx so Meta can retry.

The Graph API version is configuration rather than a source constant because
Meta versions expire and deployments must deliberately select a version still
enabled for their app.

## Runtime flow

```text
Meta webhook
  -> raw-body signature verification
  -> bounded Zod payload validation
  -> text-message extraction
  -> destination-number actor resolution
  -> existing InboundMessage
  -> handleInboundMessage (deterministic mode)
  -> existing domain state/result
  -> idempotent WhatsApp text delivery
  -> HTTP 200 acknowledgement
```

Status receipts, unsupported message types, and signed events for unconfigured
phone-number ids are acknowledged without entering the gateway. Raw provider
payloads are never passed into application code.

## Identity boundary

The signed webhook proves that Meta delivered an event for the configured app;
it does not prove that a WhatsApp identity owns an arbitrary Intra business.

- messages to `WHATSAPP_PHONE_NUMBER_ID` resolve to a buyer actor;
- messages to the optional, separate
  `WHATSAPP_BUSINESS_ONBOARDING_PHONE_NUMBER_ID` resolve to a prospective
  business owner;
- that business role can only build the existing new-business onboarding state
  and, after explicit consent, create a `PENDING_VERIFICATION` business plus a
  `DRAFT` route;
- it cannot attach itself to, edit, or activate an existing business;
- after draft creation, the existing durable conversation binds that provider
  identity to the created business id.

Using separate destination numbers is the smallest safe link for the thin
vertical slices. Account merging and proof that a WhatsApp identity may manage
an existing business are deliberately deferred; M10.18 must use a manage-token
or operator-approved linking ceremony rather than phone-number guessing.

## Retry and failure behavior

The conversation idempotency row is now inserted as a `PROCESSING` claim before
domain work. Concurrent duplicates therefore cannot both execute. A completed
result is replayed; a failed attempt releases its claim.

Outbound text has a separate idempotency claim derived from the inbound Meta
message id and output index. A domain success followed by an outbound failure
returns HTTP 502. Meta's retry replays the stored domain result and retries only
delivery. A successful delivery is not sent twice on an ordinary retry.

This first slice processes synchronously and forces deterministic conversation
interpretation to keep acknowledgement bounded. It does not add a queue. An
ambiguous network failure after Meta accepted a send but before the HTTP
response reaches Intra cannot be proven from the send request alone; delivery
status reconciliation belongs in the later notification milestone.

## Security and scope

- Secrets and tokens are server-only and read at the webhook boundary.
- Signatures use constant-time comparison against the exact raw body.
- Payload size, collection sizes, identifiers, and text length are bounded.
- Audit events contain hashed provider identifiers and statuses only—no message
  text, phone/WA id, signature, token, or authorization header.
- There is no CRM, media processing, template messaging, payment, quote
  acceptance, commitment authorization, or fulfilment action.
- Removing this route and `src/integrations/whatsapp` leaves the marketplace
  domain unchanged.

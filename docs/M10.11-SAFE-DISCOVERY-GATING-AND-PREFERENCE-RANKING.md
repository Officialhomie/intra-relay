# M10.11 — Safe discovery gating and buyer-preference ranking

## Decision

Only an **explicit fulfilment mismatch** is newly authoritative before quote
request: when a buyer requests delivery/pickup and the corresponding declared
route boolean is `false`, the supplier is removed from `requestQuote()`.

The existing `CandidateAssessment` remains authoritative for availability,
freshness, verification/readability, payment availability, fee caps, and run
budget. It was not replaced.

Location and typical turnaround remain advisory. Product type, minimum order,
complex budget matching, reputation/history, and geographic distance are not
ready for pre-quote gating.

## UNKNOWN policy

`null` fulfilment, missing service area, non-overlapping free-text areas, and
missing/unparseable typical turnaround remain UNKNOWN. They never become MATCH
or NO_MATCH and do not by themselves remove a candidate. The trace marks such
candidates `RETAINED_UNKNOWN`; a supplier quote can resolve the uncertainty.

## Planning and trace

The live path is now discovery → existing CandidateAssessment →
CandidateEvaluation → narrow authoritative gate → requestQuote. A delivery
`NO_MATCH` is recorded as `AUTHORITATIVE_FULFILMENT_MISMATCH`, is moved out of
`plan.toQuery`, and never creates a quote-request task. Candidate trace entries
record `EXCLUDED`, `RETAINED_MATCH`, `RETAINED_UNKNOWN`, or
`RETAINED_ADVISORY`, alongside the prior policy comparison.

An advisory disagreement remains observable: a clearly too-slow typical
turnaround can disagree with evaluation while remaining requestable.

## Buyer preference ranking

The existing `UserIntent.optimization` and budget now flow through the existing
conversation `RunBrief` into `BuyerIntent` and `selectOffer`; no raw
conversation text is re-parsed.

| Preference         | Behaviour                                                                             |
| ------------------ | ------------------------------------------------------------------------------------- |
| CHEAPEST           | Lowest comparable total price first                                                   |
| FASTEST / EARLIEST | Shortest stated, parseable turnaround first                                           |
| WITHIN_BUDGET      | Comparable offers within the stated budget are favoured, never automatically rejected |
| BEST_VALUE         | Existing balanced score retained                                                      |
| AVAILABLE_NOW      | Balanced score retained: offers have no reliable immediate-availability signal        |
| NEAREST            | Balanced score retained: free-text areas are not distance evidence                    |
| no preference      | Existing balanced score unchanged                                                     |

Every applied or unsupported preference adds a buyer-readable `DecisionReason`
and selection explanation. Budget is a ranking signal only: a quote is not
rejected from an indicative or non-comparable price.

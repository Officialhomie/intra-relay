### The app mark (source: `scripts/generate-icons.mjs`)

> "The mark: Intra Relay — two nodes and the line between them (a request handed
> from one party to the other), in the 'calm clinic' forest green."

An inline SVG: a rounded square (`rx=96` on a 512 canvas) in `#0f3e17`, a
horizontal line between two circles — one **filled** linen (`#fffefc`, the
sender), one **outlined** (the receiver). It is a genuinely good conceptual mark
(a handoff), but it is:

- rendered **only** into the 4 PWA PNGs — never used in the running UI;
- in the **superseded** green palette;
- **not** available as a source SVG committed anywhere (only the JS string that
  produces it);
- dependent on `sharp`, which is **not a project dependency** — the script needs
  a global/`npx` install to re-run.

### Typography assets

**None.** `src/styles/tokens.css`:

- `--font-sans`: `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`
- `--font-serif`: `"Iowan Old Style", "Palatino Linotype", Palatino, Georgia, ui-serif, serif`
- `--font-mono`: `ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, monospace`

No `next/font`, no `@font-face`, no `public/fonts/`. ADR-009 and ADR-022 both
**forbid a web-font fetch at build**. Consequence: the "editorial serif" identity
(`<h1>`/`<h2>`/`<h3>` are `font-serif` weight 300) renders as **Iowan Old Style
on Apple devices and Georgia on Android/Windows** — i.e. Georgia for the primary
target audience (Nigerian students on inexpensive Android phones).

### Illustrations / photography / decorative graphics

# 3. Missing assets the redesigned experience needs

Ordered by impact. Every entry: **why it's needed**, **where**, **who sees it**,
**style**, **format**, **dimensions**, **light/dark**, **mobile**,
**generate vs design**. Generation prompts are in
[`14-LOVABLE-ASSET-PROMPTS.md`](14-LOVABLE-ASSET-PROMPTS.md).

## 3.1 Brand & identity (design, don't generate)

### A1 — Intra app mark (primary symbol)

- **Why**: there is no canonical logo; three inconsistent marks exist.
- **Where**: favicon, PWA icons (all 4 sizes), `Header`, `OutcomePanel` success
  moments, the install prompt, OG image, `/offline`.
- **Who**: everyone, constantly.
- **Style**: the "handoff" concept — two nodes + a connecting line — rebuilt as a
  clean geometric mark. Ink (`#1f1e1d`) on ivory, or reversed linen on ink for
  the app-icon tile. No gradient, no 3D, single stroke weight. Must read at
  16px.
- **Format**: **source SVG** (committed to `public/` or `src/assets/`), plus
  derived PNGs (16, 32, 180, 192, 512, maskable-512).
- **Dimensions**: 512×512 master; maskable variant with a ≥ 20% safe-zone.
- **Light/dark**: one ink version + one reversed version. No dark-mode app, but
  OS icon tiles and some browsers invert.
- **Mobile**: this IS the mobile home-screen icon — test at 48/72/96/192.
- **Generate vs design**: **design** (it's the brand). Provide the concept to a
  designer or iterate a few SVG drafts by hand; do not accept an AI raster.

### A2 — Intra wordmark

- **Why**: `Header` uses plain text; there is no set wordmark treatment.
- **Where**: `Header`, `Footer`, OG image, onboarding, `/docs`.
- **Style**: "Intra" set in the display face (or a lightly customised sans),
  weight 400–500, tight tracking, lowercase or title-case — a single locked
  lockup with the mark to its left, and a mark-only variant for tight spaces
  (mobile header at 360px).
- **Format**: SVG (horizontal lockup + mark-only) + a CSS spec so it can be
  recreated in text where an asset would be overkill.
- **Generate vs design**: **design**.

### A3 — Favicon

- **Why**: **there is no proper favicon** — no `favicon.ico`, no
  `src/app/icon.svg`, no `src/app/favicon.*` route. `metadata.icons.icon` points
  a browser at `/icons/icon-192.png` — a 192px PNG (oversized for a 16–32px tab
  slot) in the **stale green** palette. The tab icon is therefore a
  badly-downscaled wrong-colour mark.
- **Where**: browser tab, bookmarks, history.
- **Format**: `src/app/icon.svg` (Next 15 auto-serves it) — the A1 mark
  simplified for 16–32px; plus a `favicon.ico` (16+32+48) fallback.
- **Generate vs design**: **derive from A1**.

# 5. What must NOT happen in the asset pass

- **No stock photography.** Not on the landing page, not in onboarding, not in
  empty states.
- **No fabricated merchant imagery, avatars, logos, or "trusted by" strips.**
  `CLAUDE.md` §4.1 forbids fabricated merchant evidence; there are no user
  accounts so avatars are meaningless.
- **No blockchain / crypto decorative imagery** — no chains, no coins, no
  glowing nodes, no "web3" gradients. Celo/USDC marks appear only where §3.3
  specifies.
- **No AI mascot, no "thinking" animation, no chat-bot avatar.** The agent is a
  progress spine + a narrative, not a character.
- **No dozens of bespoke icons.** lucide is the icon system. The only custom
  glyph is the app mark.
- **No dark-mode asset variants** beyond the single reversed app-mark (the app
  is light-only by decision, ADR-009/022).
- **No animated illustrations / Lottie.** The B-series are static SVGs; motion is
  handled by the transition system ([`12` §14](12-DESIGN-SYSTEM-RECOMMENDATION.md#14-motion)).
